# 歩行と走行のゲームバランス検証（2026-10-20）

## 対象と作業分離

Issue #9/#10 のうち、公開ステージ1〜7の速度・学習導線だけを対象とする。ステージ8は別セッションで開発中のため、パーサー・スイッチ・ステージ8・ランキング版は変更しない。

現状の走行倍率は1.3倍。既存のステージ1〜7で登録済みの「はしる＋条件」解法はすべて成功するため、走行を選ぶデメリットがほぼない。共通物理を先に変更すると公式tickとサーバー再実行検証が変わるため、まず独立した実験ステージで速度選択を試す。

## 実験ステージ

`experiments/stages/pace-route.json` は以下の構成。マニフェストには含めず、公開・採点・ランキングへ影響しない。

- 600: おばけ
- 700: 幅80の穴
- 1200: かべ
- 1600: ゴール

ゴーストの直後に穴があるため、同じ「まえとぶ」でも速度によってジャンプの頂点と着地位置が変わる。歩行と速度切替、危険の種類を見分ける高度な解法を比較できる。

| 解法 | 入力例 | 検証の意図 |
| --- | --- | --- |
| 歩行 | `まえとぶ / おばけしゃがむ` | 短いコードで安全にクリア |
| 無調整の走行 | `はしる / まえとぶ / おばけしゃがむ` | 速いだけでは穴に落ちる |
| 走行→歩行 | `はしる / あなあるく / まえとぶ / おばけしゃがむ` | 危険の手前で減速して成功 |
| 走行→歩行→走行 | 上に `かべはしる` を追加 | 安全な区間では再加速できる |
| 条件別の高速解法 | `はしる / おばけしゃがむ / あなとぶ / かべとぶ` | 障害物を見分ければ減速せず成功する |

上の「/」は説明用の改行区切り。実際のコードは1命令1行で入力する。

## 再現と受け入れ条件

`npm run analyze:pace` は公開ステージ1〜7の初心者/短縮/高速/明示的な歩行・走行を統一フォーマットで比較し、実験ステージの失敗理由・tick・文字数・積も表示する。理論最適ではなく、試した解法の既知最良値だけを報告する。

`tests/stage-pace.test.mjs` では、歩行成功・走行失敗・速度切替成功、速度変化の遷移と十分な区間間隔、公式tickの決定論、公開ステージ1〜7の既存基準を検査する。

## 公開ステージ調整の次の工程

1. 実験で有効な「危険の手前で歩き、通過後に走る」を、学習順序上ふさわしいステージへ導入する候補を比較する。現状はステージ4と5が候補だが、どちらも本PRでは改変しない。
2. 最初に出す解法を歩行で確実に成功するようにして、短縮解法と高速解法を明確に分ける。走行の失敗理由が視覚・ヒント・リザルトから推測できることを確認する。
3. 反応や速度切替が1〜2tick単位の際どい条件にならないよう、配置を段階的に変えて前後の許容範囲を確かめる。
4. 公開JSONを変更する際は、該当ステージの個別`stageVersion`、`score.ts`の参照値、`worker/validation.mjs`の再実行条件、stage-checks、UI/E2Eを一括で更新する。既存ステージ版の記録を混ぜない。
5. 会場実機での体験評価はIssue #12へ残す。

`runMultiplier`の変更や速度の加減速曲線追加は、配置とプログラムの実験で解決できない問題が見つかってから検討する。

## ステージ5への組込み候補（公開前・別fixture）

`experiments/stages/stage-5-pace-candidate.json` は公開ステージ5をコピーし、次の2点だけを動かした比較用候補。

- 2体目のおばけ: 1000 → 1340
- 穴: 1440 → 1456（幅80は据え置き）

壁とおばけが同じ座標に重なる課題、後半の単独のおばけ、穴、最後の壁は維持する。後半のおばけと穴を近接させることで、「まえとぶ」という広い命令と速度選択の違いを試す。初心者と対象を特定した高速解法は変えずにクリアできることをCIで確認する。歩行の安全性と走行の事故、減速による復旧も対照実験として検証する。

この配置はまだ実地の学習効果・視認性・難度を評価していない。ステージ5はしゃがみジャンプが主題であり、速度の追加学習による認知負荷が高くなる場合は、この配置を別の追加ステージに移す。正式なステージ5への組込みは、既存`2026-10-20-r1`と新`r2`のランキング参照を両方保持できる版管理を先に検証してから判断する。

## ステージ5 r2 公開改訂（2026-10-20）

非公開候補の配置が自動検証で成立したため、ステージ5のみ次の条件で公開する。

- `solo-ghost` を 1000 → 1340、`middle-hole` を 1440 → 1456 に移動（穴の幅80、他の障害物とゴールは維持）。
- 学習目標に「走る・歩くをきりかえて安全に進める」を加え、既存の同時ジャンプ・しゃがみ課題を維持。ヒントと穴の失敗時メッセージを改善。
- `manifest.stages[].version` の **stage-5だけ** `2026-10-20-r1` → `2026-10-20-r2` に更新。全体の `manifest.version` は据え置き。
- `getScoreReference` にr2を追加し、初版 `2025-10-26` と旧r1の参照点（746tick/14文字/10444積）も保持。r2の既知の基準解法は物理値・ゴール・走行速度が同じため、746tick/14文字/10444積を使用する。理論最適の主張ではない。
- `validateScope` は旧版もGETで受理、`validateRunPayload` は現行r2への新規投稿だけを受理する。ステージ5のサーバー再実行には改訂後JSONを使用。
- `stage-checks/stage-5.json` へ「歩行成功/無調整走行失敗（穴）/あなあるくで回復/正確な高速解法成功」を登録し、既存の公式基準・同時アクション解法が変わらないことを再検証。
- ステージ8は独立セッションの現行状態を保持し、配置・言語仕様・ランキングを変更しない。
