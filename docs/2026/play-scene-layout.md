# プレイ画面の構図と操作導線

## 目的

ことグラムの主要体験は命令を入力してゲームを動かすこと。ステージ選択とタイトルの冒険マップに続き、プレイ中もゲーム面を画面の主役として扱う。

## 変更

- デスクトップの画面は左が命令入力、右が大きなゲーム領域。比率を約4:6とする
- ゲーム領域の重複ヘッダーを廃止し、実行中の状態だけを小さく表示する
- Canvas周囲は淡い緑と紺色のフレームで他シーンとの色調を揃える
- 幅960px以下では入力とゲーム領域を縦に配置する
- 縦配置では「動かす」実行後にゲーム位置へ画面を動かし、失敗またはクリア画面からコード編集に戻ると入力位置を表示する
- 移動は実行・結果への直接操作でのみ行い、モーション削減が指定されていれば即時に切り替える

## 不変条件

Game Core、プログラム解析、公式tick、ステージJSON、採点、ランキングは一切変更しない。DOMのゲーム面が大きくなってもCanvas描画の内部解像度と結果を維持する。

## 検証

- PCではゲーム領域がエディターより幅広い
- 390×844では単列表示、ゲームCanvasがDOMから消えない
- プレイ・失敗・再試行・クリアの従来E2Eが通る
- 既存のスクリーンショットに加え、ワークスペース全体の構図を保存する
