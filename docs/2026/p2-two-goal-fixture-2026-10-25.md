# P2 分岐ゴール・非公開実験受け入れ（2026-10-25）

対象: Issue #153、PR #155。既存の公開30ステージは無変更。

## 遊び方・言語

従来の単一ゴールでは、ゴールに到達するとそのままクリアになる。新機能は **2つのgoal objectを明記したステージだけ** 有効になる。

```text
こいんとる
```

手前の「ちかみち」ゴールでクリアする。先のゴールへの追加移動はしない。

```text
ごーるをみおくる
こいんとる
かべとぶ
```

手前のゴールを明示的に見送り、「ごほうび」ゴールまで進む。見送りは近くの手前ゴールだけが対象となり、奥の最終ゴールを見送って失敗することはない。スイッチの「みおくる」は従来どおりスイッチにだけ作用する。

## 仕様

- Stage JSON: `goal` は最後のゴールの位置。明示的なgoal objectが2個あるときだけ分岐。各goalに一意の`id`、`position`、整数`bonusBp`。
- 手前のgoalの`bonusBp`は5000〜9500、奥は10000。ステージの最終`goal`は奥と一致。距離240以上、手前の初期アプローチを確保。
- ひとつのgoalしかない場合は`bonusBp`を設定できず、従来の10000bp固定。どの公開ステージにも変更なし。
- `ごーるをみおくる`を実行したとき、手前goalのIDだけが`skipped=true`となる。選択したゴールを`selectedGoalId`と`goalBonusBp`に保持。
- ステージ内のおすすめ言葉の一覧は、明示2ゴールのときにのみゴールと見送りを表示。共通パーサーに登録した語句は非表示ステージでも構文解析自体は可能。
- 得点計算の`completionBp`は既存のコイン率×スイッチ見送り率×ゴール倍率。固定小数点、最低1200bpは維持。タイム・文字数・総合は従来と同じ計算式と比較順。
- 近道ゴールは「①・ちかみち」、奥は「☆・ごほうび」、見送ったゴールには矢印と「みおくった」。色だけでは判別させない。
- Workerは自称tickや自称達成率を受理せず、提出されたソースをGame Coreで再実行して検証。`verifyStageRunResult`は非公開fixtureにも同じリプレイを適用するための検証関数。

## 検証

`experiments/stages/two-goal-route.json` では、近道ゴール位置540/倍率7000bp、奥のゴール位置1160/倍率10000bp、手前と奥のコイン計2枚、奥に壁1つを置いた。

- 近道のみ: 最初のコインを回収して近道ゴールに到達。コイン達成率65%×ゴール70%=45.5%。
- 奥へ進む: 最初のゴールを見送り、2枚のコインを回収し、壁を越えて奥のゴールで100%。
- 見送るだけで奥の障害物を無視: 壁への衝突で失敗。
- 旧30ステージ: schema受理、旧stage-1の712tick、Worker再実行検証を維持。
- 近道/遠方の両ルートを100回ずつ新規ゲームで決定論的に再実行。
- 不正な重複ID、ボーナス値、2個以上の過剰ゴール、位置不正、改ざんしたtick/達成率を拒否。
- 描画: 色以外のシンボル/日本語ラベルが存在することを検証。

この段階では「学習者に複数のゴール選択肢が見える」実験を実装した。実際の公開ステージでのバランス調整は別PRにし、公開時には`stageVersion`・公式基準値・Workerの最新リプレイ定義・旧ランキングGETを同時更新する。現行ランキングのスコープは変えない。

## デプロイ

公開ステージを新しく配備していないため、現行30面のランキング境界は変更なし。ただしフロントとWorkerのCore/辞書が連携するため、公開ステージで採用する際はAPIを先に、フロントを後にデプロイする。会場実機・児童の理解度テストはIssue #12に分離。
