# P1: 通常学習ルートと速度選択を設計する

更新日: 2026-10-25

## ねらい

1. 隠しコマンドを知らなくても、30ステージすべてを通常の入力で解けることを自動検証で保証する。
2. 第2世界と第3世界に、走る速さと命令の正確さのトレードオフを増やす。
3. 物理・配置を変更した公開ステージにだけ別の版を割り当て、旧ランキングの照会を維持する。
4. 現状の既知解法と理論最適を区別し、短縮・最速・総合・隠しコマンドの利益を同じ条件で比較する。

## 通常の学習ルート

`stage-checks` のロール定義:

- `beginner`: 既存の公式スコア参照を再現する基準コード。過去に隠しコマンドが混在したことがあるため、必ずしも通常の学習に推奨するコードではない。
- `learning`: 隠し動作を一切使用せずクリアする学習用解法。パーサーのASTに `powerJump` または `sprint` があれば検証失敗。既存の `beginner` が隠し動作を使わない場合は、そのまま学習用解法として扱う。
- `short`, `fast`: 既知の文字数・時間短縮例。
- `negative`, `regression`: 失敗と各種操作を確認する回帰ケース。

ステージ12、18、21、24、29、30に `learning` ケースを登録。既存の `beginner` を変えると公式基準と既存ランキング表示の意味が変わるため、今回の変更では既存のスコア参照を維持する。学習用の解法が必ず1000点になるわけではないことに注意。全ステージの学習用ルートを自動テストで保護する。

## 2つの公開ステージの改訂

| ステージ | 旧版 | 新版 | 変更 |
| --- | --- | --- | --- |
| stage-13（第2世界） | 2026-10-20-r1 | 2026-10-25-r2 | おばけのすぐ後に穴を配置し、穴のジャンプ検知を穴幅に合わせて補正 |
| stage-25（第3世界） | 2026-10-20-r1 | 2026-10-25-r2 | 最後のおばけのすぐ後に穴を配置し、穴のジャンプ検知を穴幅に合わせて補正 |

両ステージで検証する攻略:

- 通常歩行と `まえとぶ` の汎用センサーによるクリア。
- 同じ汎用センサーで、無計画に `はしる` を追加した場合の穴への落下。
- 穴の前で `あるく` に切り替え、歩き続けるより速くクリア。
- `かべとぶ` / `あなとぶ` で対象を明示した正確な指示なら走り続けてもクリアでき、時間が短縮される。

「すべての走行が危険」ではなく、書いたコードの精度とスピードを選べる構成を目指す。入門の1〜10とステージ8の配置には変更しない。

## ランキングと公開時の注意点

- `manifest` では13・25のみ版を更新。`score.ts` には旧r1版と新r2版の参照値を両方残す。
- 現版のみランキングPOSTを受付。旧版は既存レコードのGETのみを継続できる。
- Workerが両ステージの最新JSONをimportして再実行するため、配置変更と同じリリースでAPI更新が必要。
- **公開順序はランキングAPI → フロントエンド。** APIの更新前に新版フロントを配信するとランキング登録が拒否される。
- 公式参照のtick・文字数・総合積はこの改訂で変えない。初心者プログラムの全tick再現とWorker再実行で不変性を検証する。
- ゲームの共通物理係数は変更しない。

## 30ステージの実測結果（CIで再実行）

`scripts/analyze-all-stages.mjs` の最新の確定的な頭なし（ヘッドレス）実行結果。各値は登録済み解法と指定したセンサーのプローブに限る。

- 全30ステージで秘密の行動が必要ない学習ルートを確認。
- 速度を切り替えず、対象を広く検知する `まえとぶ` + `おばけしゃがむ` + `こいんとる` では、歩行はクリアするが走行は失敗するステージが7個（5, 12, 13, 21, 24, 25, 29）。
- 同じ広い条件で「めっちゃはしる」を使うと、ステージ5・13・25で穴に落下する。
- stage-13 の通常学習ルートは1052tick、登録済みの高速ルートは602tick。
- stage-25 の通常学習ルートは1252tick、登録済みの高速ルートは716tick。
- 世界別の学習ルート平均クリアtickは第1世界717、第2世界721、第3世界1050。体験上の適正時間や難易度を保証する値ではない。

レポートはGitHub Actionsの `thirty-stage-balance` アーティファクトに毎回出力する（有効なJSON）。速度比較では既存コードの先頭の速度命令を置き換え、`walk` / `run` / `sprint` を区別する。

## 今後のP1

`npm run analyze:stages` は30ステージの `learning` を起点とする歩行/走行/隠し走行、既知解法の最速・最短・総合、隠し行動によるメリットをJSONで出力する。測定値は最良既知であり、理論上の最適は証明していない。

残る調整:
- 隠しコマンドが本当にタイム・文字数・総合のどれで有利かを分析し、弱いステージでは別解やレベル構成を改善する。
- ステージ18の広い穴と、12・21・24・29・30の連続した壁の難しさを初見ユーザーで確認する。
- ステージ全体の所要時間と行動密度を測定し、ワールドごとの難易度曲線を仕上げる。
- 学園祭実機での評価は公開前P0のIssue #12へ持ち越す。
