# ランキング投稿の公式tick再検証

## 背景

既存の結果登録APIではソース文字数と構文を検査していたが、クライアント送信の elapsedTicks を信頼していた。通信要求を直接編集すれば、クリアできないコードや任意の短いtickを投稿できる。

## 対応

- Workersへ全公開ステージのJSONを静的に同梱し、実際のGame CoreとParserで結果をサーバー側再実行する。
- クライアントと同じ固定tickでゴールすることと、公式elapsedTicksが完全一致する場合のみランキング保存。
- 最大再実行20000tick。上限超過またはゴール失敗も拒否。
- 同一runIdの冪等性/409衝突チェックは先に行い、再送時の契約を維持。
- `worker-api.test.mjs` とWrangler実起動スモークテストへtick詐称と未クリアの拒否を追加。
- manifestとサーバー再現用のステージの完全一致をNodeテストで検証。新ステージ追加時はworkerのstage importも追加する。

## 注意

- 2026 core-v2 の公式tickにのみ対応する。物理・言語・ステージJSONのルール変更時には適切なバージョン分離が必要。
- レート制限やIPベースの濫用対策は別作業。CORS制限だけでは外部の直接HTTP投稿を防げない。
- 既存の不正なランキングデータはこの変更によって自動削除されない。公開前に開発/本番DBの記録を確認する。
- マージのみで本番Workersに即反映されるわけではなく、APIの本番再デプロイが必要。
