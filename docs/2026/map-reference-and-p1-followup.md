## 実機フィードバック

- 10個ごとのワールドマップで両端のステージ看板が欠けるため、デスクトップ配置を端から8.5%〜91.5%の範囲に変更。マップ内のスクロールでアクセスする。
- ステージ一覧のページ自体は1画面内に収め、マップだけ内部スクロール（PC横、狭い画面は縦）を許可する。
- コード編集中の下見では時刻の異なる描画ループが干渉しないよう、待機中の雲の時間移動を止め、下見再描画と待機更新に同じ時計を使用する。
- 「使える言葉」は対象・動作それぞれの代表表記だけを表示し、ひみつの動きはユーザー画面から外す。
- /reference にJSON辞書の全表記、パーサー制御語、ステージ、バージョン情報、追加情報エリアを配置。ページへのリンクは作らず noindex を指定。ただしアクセス制限はしていないため秘密や個人情報を掲載しない。
- 例文は「かべをまえにみつけたらじゃんぷする」に統一。パーサー受入テストも追加。

## P1: 解法の幅と速度リスク

元の30ステージ分析では、ステージ9〜30の22件中15件の「初心者」と「短縮」の登録コードが同一だった。ステージ配置と採点基準を保持したまま、登録済みの省略表記による別解を検証ケースへ追加・置換した（21件更新、ステージ15はすでに短縮されていた）。

代表的な短縮:
- すいっち → ぼたん
- おばけ → てき
- しゃがむ → かがむ
- すごいじゃんぷ → すごいとぶ
- くりかえす → くりかえ

新たな自動検証でステージ9〜30の全22件について初心者解法より短い「short」解法が実際にクリアできることを確認する。これは既知の短縮解法であり、理論最短という保証ではない。

`npm run analyze:stages` を拡張し、各ステージについて初心者コードに「あるく」「はしる」「めっちゃはしる」を前置した比較を記録する。走行だけでクリアできるか、速度のリスクが有意かをステージ・世界単位で観察するための材料にする。

今後 #9/#10 で取り組む項目:
1. 全30ステージで計測した速度リスクの不足を特定して改修する。
2. 初心者に隠しジャンプを必須としない解法を優先し、発見型の別解は高速・総合攻略へ残す。
3. 公開ステージの配置・物理変更時はstageVersion・Worker再実行・採点基準を同期し、過去の記録を保持する。
4. 初見の小学生による学習評価と会場実機の連続稼働は #12 の公開前工程として保留。
