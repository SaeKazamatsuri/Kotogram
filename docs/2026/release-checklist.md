# 2026年 学園祭リリース前チェック

## 自動テスト

すべてのPRで次をGitHub Actionsで実行する。
- Node 22で `npm test`：Game Core・Lexer/Parser・Interpreter・採点・ソフト入力・ローカル記録・Workers API・ランキングクライアント。
- `npm run validate:stages`：全公開ステージの成功/失敗・公式tickの回帰。
- `npm ci` → `npm run build`：Nuxtバンドル検証。
- `npx wrangler deploy --config wrangler.api.jsonc --dry-run`：Cloudflare APIのバンドルと設定検証。クラウドへデプロイしない。

## 手動E2E（お兄ちゃんからのFB前提）

1. ステージ1〜3の成功・失敗・再挑戦とスタート/ゴールの動作を確認。
2. ひらがなソフトキーボードだけで有効命令を入力し、途中への挿入・選択置換・濁点・半濁点・小書き・数字・改行・Backspace・カーソル移動を検証。
3. IMEで入力後にソフトキーボードへ切り替え、日本語変換中の入力破損がないことを確認。
4. `はしる`、`あるく` の速度差と壁・穴・おばけ・しゃがみジャンプの失敗/成功を複数解法で検証。
5. クリア画面の3スコア・1000点超え・最速/最短/総合の別々の自己ベストを確認。
6. Workers開発APIを接続して空欄名→ゲスト連番、任意名、同名別プレイヤー、送信障害→再送、3ランキングタブを検証。
7. 通信を切断してもゲーム本体が進行できることを確認。
8. 共用端末「リセット」で編集・自己ベスト・ゲスト識別子を初期化し、同じブラウザの他アプリのlocalStorageを消さないことを確認。
9. 1366×768、1920×1080、125%表示倍率、PCマウス/日本語IME環境でキーが重なったり切れないことを確認。

## 本番未実施

Cloudflareアカウント接続、本番Workersデプロイ、SQLite-backed DO migration、CORS Origin設定、静的フロントの本番構築、本番ブラウザE2Eはユーザー環境で検証する。PR段階の成功は本番デプロイを意味しない。

会場用のデータ保存期間と記録削除手順、運営用リセットの権限設計、個人情報を使わないニックネーム案内は運用前に別途最終確認が必要。
