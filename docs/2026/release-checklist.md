# 2026年 学園祭リリース前チェック

## 自動テスト

すべてのPRで次をGitHub Actionsで実行する。
- Node 22で `npm test`：Game Core・Lexer/Parser・Interpreter・採点・ソフト入力・ローカル記録・Workers API・ランキングクライアント。
- `npm run validate:stages`：全公開ステージの成功/失敗・公式tickの回帰。
- `npm ci` → `npm run lint` → `npm run typecheck` → `npm run build`：静的解析、共通TSモジュールの厳格型検査、Nuxtバンドル検証。
- `npx wrangler deploy --config wrangler.api.jsonc --dry-run`：Cloudflare APIのバンドルと設定検証。クラウドへデプロイしない。
- `npm run explore:stages`：候補数/実行tick/文字数/処理時間に制限を設け、各ステージの既知の最良解を独立集計する。公開スコア基準は変更しない。

## 手動E2E（お兄ちゃんからのFB前提）

1. ステージ1〜5の成功・失敗・再挑戦とスタート/ゴールの動作を確認。各クリア後の「つぎへ」が次のステージをロードし、ステージ5クリア後はホームに戻ること。
2. ひらがなソフトキーボードだけで有効命令を入力し、途中への挿入・選択置換・濁点・半濁点・小書き・数字・改行・Backspace・カーソル移動を検証。
3. IMEで入力後にソフトキーボードへ切り替え、日本語変換中の入力破損がないことを確認。
4. `はしる`、`あるく` の速度差と壁・穴・おばけ・しゃがみジャンプの失敗/成功を複数解法で検証。ステージ4は壁の回数指定が3回だと失敗・4回だと成功、ステージ5は同位置の壁＋おばけに対してジャンプ＋しゃがみの両立を確認。
5. ステージ4の夕焼け・ステージ5の薄暮の背景、状態表示と二重障害物の強調表示を確認。画像取得に失敗した場合の代替描画と、視覚を変えてもクリアtickが変わらないことを確認。
6. クリア画面の3スコア・1000点超え・最速/最短/総合の別々の自己ベストを確認。
7. Workers開発APIを接続して空欄名→ゲスト連番、任意名、同名別プレイヤー、送信障害→再送、3ランキングタブを検証。
8. 通信を切断してもゲーム本体が進行できることを確認。
9. 共用端末「リセット」で編集・自己ベスト・ゲスト識別子を初期化し、同じブラウザの他アプリのlocalStorageを消さないことを確認。
10. 1366×768、1920×1080、125%表示倍率、PCマウス/日本語IME環境でキーが重なったり切れないことを確認。

## 本番未実施

Cloudflareアカウント接続、本番Workersデプロイ、SQLite-backed DO migration、CORS Origin設定、静的フロントの本番構築、本番ブラウザE2Eはユーザー環境で検証する。PR段階の成功は本番デプロイを意味しない。

会場用のデータ保存期間と記録削除手順、運営用リセットの権限設計、個人情報を使わないニックネーム案内は運用前に別途最終確認が必要。

## PR #26〜#32 検証時の確認順

1. CIでテスト、ステージ全件、候補探索、静的解析、Nuxt/Workersビルドを確認。
2. 新しい体験者としてステージ1から進行し、ステージ4〜5が順番に解放されることを確認。
3. ステージ4/5で短縮・走行の複数解法を試し、得点1000超・ランキング登録・再挑戦を確認。
4. エディタに途中入力した状態で「つぎへ」を押し、次ステージへ前のコードや結果が持ち越されないことを確認。
5. ネット切断・復帰、ブラウザ戻る、再読み込み、タブ休止、画面倍率125%、初期化と再開を確認。
6. 最後に会場と同等のPCでスタッフが一連の体験を通し、失敗時の復旧手順を実演する。

型検査はGame Core・Parser・ランキング・探索等の共有TSモジュールを対象とし、Vueテンプレート全体を厳密に型検査するものではない。Nuxt buildは別ジョブで検証する。未実施の実機結果を「確認済み」にしない。
