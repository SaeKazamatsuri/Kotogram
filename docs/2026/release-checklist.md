- [ ] 同一ブラウザからのCORSプリフライト・記録送信・ランキング3種類の取得を実機で確認し、結果を記録。

APIヘルスの読み取り確認:

```powershell
Invoke-RestMethod -Uri "https://kotogram-api.sae-chan.net/api/health"
```

読み取り専用の公開スモークテスト:

```powershell
npm run smoke:production
```

`smoke:production` はランキングへの書き込みをしない。実際の登録・同時登録の試験は開発/検証環境で実施する。

## PRごとの自動品質チェック

GitHub Actionsの各PRで以下を実行する。

- `npm test` : Game Core、Lexer/Parser、Interpreter、採点、ソフトキーボード、ランキング、API、画面の状態管理、待機アニメーション、低FPS/タブ復帰。
- `npm run validate:stages` : 公開中の7ステージと基準解法/失敗解法を検証。
- `npm run explore:stages -- --max-candidates=128 --max-ms=5000` : 探索コストを制限して候補解を集計。
- `npm run lint`、`npm run typecheck`、`npm run build`、`npm run generate`。
- フロントエンドと開発/本番APIの `wrangler deploy --dry-run`。本番APIのCustom DomainとCORS originの設定を検査。
- Chromiumのデスクトップ・モバイルサイズでPlaywrightのブラウザE2E。通信障害時の再読み込み、編集中の採点、共用PCリセット時の遅延応答を検証。
- ローカルWorkersとSQLite-backed Durable ObjectsによるAPI統合試験。

CIではVueテンプレート全体を型検査するとは限らないため、ビルドと実画面での確認を併用する。

## 会場PCでの実機シナリオ

- [ ] 1366×768と1920×1080、125%拡大、日本語IME、マウスで画面のはみ出しと入力の重なりがない。
- [ ] ステージ1〜7を順番に開き、成功・失敗・再挑戦・次のステージ遷移を確認する。最終ステージの「次へ」はステージ一覧へ戻る。
- [ ] 物理キーボードを使わずに、濁点/半濁点/小書き/数字/空白/改行/削除/カーソル/選択範囲置換を行い、命令が実行できる。
- [ ] 日本語IMEの変換中にソフトキーボードを利用しても入力内容や選択範囲が壊れない。
- [ ] ステージ4の回数制限、ステージ5のしゃがみジャンプ、ステージ6のコイン、ステージ7のスイッチと扉をそれぞれ検証する。
- [ ] プレイヤーの待機・走行・ジャンプ・しゃがみと、壁・穴・おばけ・コイン・スイッチ・扉の見た目が判定範囲と整合する。
- [ ] 低FPS・タブ休止復帰後もゲームが止まらず、公式tickの扱いが想定と一致する。
- [ ] クリア直前にエディタを書き換えても実行開始時のコードで文字数・スコア・ランキング記録を計算する。
- [ ] タイム・文字数・総合の3スコア、1000点超え、各指標で別々の自己ベストが成立する。
- [ ] ランキングAPIにアクセスできない場合もゲームは遊べ、再送時に同じrunIdを使う。12秒の通信タイムアウト後に送信操作を再試行できる。
- [ ] 名前未入力のゲスト連番、任意名、同名の別プレイヤー、ランキング3タブを確認する。
- [ ] 「次の人へ」でコード・名前・端末側の自己記録が消え、別サイトや他アプリのlocalStorageを消さない。
- [ ] ランキング送信中に画面を離れた後、前利用者の遅い応答で名前が復活しない。
- [ ] スタッフがネットワーク切断→復帰、ステージ読込失敗→再試行、表示倍率変更、ブラウザ再起動から復旧できる。

## 学園祭の運用判定

- [ ] 想定する来場者の一連の体験時間、各ステージでのつまずき、ゲームバランスを測定する。
- [ ] 共用PCで連続体験を実施し、ゲスト名・コード・ローカル記録が次の来場者へ漏れない。
- [ ] クラウドランキングの記録の保持期間、削除手順、公開名の注意書きを決定する。
- [ ] 多端末同時登録、オフラインからの再送、DOの競合/重複記録の実機負荷を確認する。
- [ ] 障害時の担当者と、表示・入力・通信の切り分け手順をスタッフへ共有する。
