# 品質保証・自動テスト・イベント受け入れ

## 1. 品質方針

2025年のプロトタイプを2026年の学園祭で安定運用しながら拡張するため、ゲームの決定性、言語の一貫性、ステージのクリア可能性、ランキングの正常動作を回帰テストで担保する。

## 2. テストピラミッド

- 単体テスト: Lexer、Parser、文字数、Score、Session/RunId処理、センサー、物理、アクション合成。
- 統合テスト: AST → Interpreter → GameState → クリア / 失敗 → スコア。
- ステージテスト: 既知の複数解法と失敗解法を全ステージで実行。
- UI/E2E: 物理入力、ソフトキーボード、クリア画面、3ランキング、リセット。
- イベント試験: 共用PCで連続プレイ・ネットワーク不調・再読み込み・複数人利用。

候補ツール: Vitest（TSユニット / 統合）、Playwright（ブラウザ/E2E）、Zod等（スキーマ検証）。採用ライブラリは依存負荷を確認して確定する。

## 3. 言語の必須ケース

- `かべとぶ` はすべての壁へ反応。
- `かべとあなとぶ` は壁または穴に反応。
- `かべ3かいとぶ` は3回受理後発火停止。
- 同じ壁が数tick見えても1回として扱う。
- ジャンプ不能時のイベントは成功発火回数を消費しない。
- `3かいとぶ` と `かべ3かいとぶ` の意味が混同されない。
- 丁寧な文章と短縮構文が同じ意味のASTに解析される。
- `かべとあなとぶ` の接続詞と動詞の `と` が曖昧に分割されない。
- 改行、余分な空白、全角数字、未知語、終端なしブロック、上限超過の診断。
- 同じ辞書・言語バージョンで同じ解釈になる。

## 4. ゲームの必須ケース

- しゃがみジャンプが成立する。
- jumpとcrouchの同時実行と、同一アクションの重複抑制。
- walk/run速度変更とジャンプの組合せ。
- 壁、穴、おばけに対する成功/失敗と境界接触。
- 低FPS・高FPS・非表示タブ復帰でも公式tick数が同じ。
- 同じ入力で100回実行し、成功可否・elapsedTicksが毎回同じ。
- 長い実行・悪い構文・到達不能ステージでもタイムアウトで終了。
- 再実行でルール消費数、障害物状態、ジャンプ状態が正しくリセット。

## 5. ランキングの必須ケース

- 3ランキングがそれぞれ別の最良ランを保持。
- 基準より良い記録は1000点を超えて表示される。
- スコアの丸めが順位へ悪影響を及ぼさない。
- 同点は同順位、表示順のみ安定。
- 名前空欄時にサーバーが「ゲストN」を付与。
- 名前が重複してもplayerIdが異なれば別記録。
- runIdの重複送信で二重登録しない。
- stageVersion / engineVersion等が異なる記録を混在しない。
- 通信エラーでもクリア結果画面から編集・再実行できる。
- プレイ端末をリセットしてもクラウドの既存ランキングは残る。

## 6. UI / ソフトキーボード

- 五十音・濁音・半濁音・小書き・数字・改行・削除。
- 任意カーソル位置への挿入、選択範囲の置換。
- 物理入力とソフト入力を交互に使っても入力が壊れない。
- IME変換途中で日本語を失わない。
- エラー行とその説明が分かる。
- ソフトキーボード表示時にゲーム画面・入力画面のレイアウトが使える。
- 固定文字サイズで主要対応画面に表示ズレがない。

## 7. ステージ自動検証

全公開ステージで:
- JSONスキーマ検証。
- 初心者向け解法、短縮解法、高速化解法の実行。
- 意図した失敗解法での失敗。
- タイム、文字数、時間×文字数の記録。
- タイム・文字数の改善余地があるかのチェック。
- 設定された基準値とテスト記録の整合性。
- 実行上限と探索範囲の明示。

## 8. CIゲート

推奨順序:
1. `npm ci`
2. `npm run lint`（scriptを整備）
3. `npm run typecheck`（scriptを整備）
4. `npm run test`（Vitest等）
5. `npm run validate:stages`（作成）
6. `npm run build`
7. 必要ならPlaywrightのE2E

コミットごとに少なくとも主要コアとステージ検証を実行する。デプロイは本番ステージ・基準値とバージョンの整合が取れてから行う。

## 9. 受入試験 / 学園祭当日

- スタッフの模擬説明のみで初級ステージをクリアできるか。
- マウスのみでの入力完遂。
- 2人以上が順番に同じ端末を使っても前利用者のコードが残らない。
- 複数端末から同一ステージランキングへ登録できる。
- 保存できない間もゲームは動作する。復旧時の扱いが分かる。
- 長時間連続使用でイベントリスナー・RAF・タイマーが累積しない。
- 初回読み込み・画像のロード失敗時にゲームが使用不能にならない。
- 2025年版の体験機能からの回帰がない。
- スタッフが端末・ネットワークのトラブルを手順書で復旧できる。

## 10. 計測・改善のサイクル

1. ステージ制作者が基準解法を定義。
2. 自動検証でタイム・文字数・失敗理由を出力。
3. 実際のプレイテストで予期しない解法・誤操作・難所を収集。
4. 速度・センサー・配置・ヒントを調整。
5. ベースラインを再計算し、公開前にランキングバージョンを凍結。
6. 再度すべてのステージ回帰テストを通す。
