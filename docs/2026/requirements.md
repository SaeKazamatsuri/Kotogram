# 要件定義・スコープ

## 1. 背景・ゴール

2025年の学園祭において、ひらがなによる命令入力で障害物を回避するプロトタイプを運用した。2026年は安定稼働と保守可能な構造を優先しながら、命令短縮・クリアタイム短縮を競う体験に発展させる。

### 主要目的

- 低学年を含む子どもが、試行錯誤を通じて条件、順序、繰り返し、抽象化を理解できる。
- 正しいプログラムほど必ずしも短い・速いとは限らないことを学び、解法を改善する楽しさを提供する。
- 同じステージに初心者の明示的な解法と上級者の短縮解法が共存する。
- 学園祭の共用PCで途切れずに繰り返し体験してもらえる。
- 自宅ではアカウント不要でサイトを開き、再度ステージ1から始められる。

### 成功基準案（数値は運用前の検証で決定）

- 昨年の主要ステージを新エンジンで再現できる。
- 同じステージ・プログラム・エンジンバージョンでは、端末FPSにかかわらずクリア可否と公式tick数が一致する。
- 操作開始から初回実行まで、スタッフの最小限の案内で進められる。
- 初心者向け解法と短縮 / 高速化解法の双方を持つステージが存在する。
- 全ステージで到達可能な解法を自動検証できる。
- ランキングの保存失敗時もゲーム本体は継続できる。

## 2. 利用者と想定環境

| 利用者 | 目的・前提 |
| --- | --- |
| 小学生 / 初回体験者 | ひらがな入力、実行、クリア、スコア比較 |
| 小学生 / 再挑戦者 | タイム・文字数の改善、別解の発見 |
| 運営スタッフ | 体験案内、端末リセット、トラブル時の復旧 |
| 開発・ステージ制作者 | ステージ追加、基準スコア設定、回帰・自動検証 |

- 中心環境は学園祭のPC + マウス、物理キーボード。文字入力が困難な利用者にマウス操作のソフトキーボードを提供する。
- タブレット等の対応は端末要件の決定後に判断する。
- 体験の目安は2025年版の約15分を参照し、2026年の正式目標時間は現地検証で決める。

## 3. ユーザー体験

1. ホームからステージを選ぶ。初級ステージはすぐ試せる。
2. 自由テキストエディタに命令を書く。ソフトキーボードで1文字ずつ入力可能。
3. 入力中の有効性・エラーを行単位で理解できる。
4. 実行するとキャラクターが自動でスタートし、入力されたプログラムが実行される。
5. 障害物で失敗したら原因とヒントを表示し、すぐ編集・再実行できる。
6. クリアしたらゲーム内タイム・文字数・総合点を確認できる。
7. 任意のニックネームを入力してランキングに登録。空欄なら「ゲスト1」などの番号名。
8. より速いプログラム、より短いプログラムで再挑戦できる。

## 4. 必須機能（P0）

### 言語

- ひらがな中心の自由入力。インデントの深さやTabに意味を持たせない。
- 条件と動作の単語、表記ゆれ、短縮構文を定義し、同じ意味の入力を同じASTへ変換。
- 複合条件 OR（例: `かべとあなとぶ`）。
- 条件付きルールの継続監視と回数限定発火。
- 無条件命令、ブロック構文と回数制限の意味を定義。
- パースエラーの行・原因・修正ヒントを提示。
- 予想外の入力や無制限の繰り返しでハングしない上限設定。

### ゲーム

- ゲーム状態と描画を分離する。
- 固定tickの決定論的なシミュレーション。
- 条件付き命令が同種すべての障害物に反応。
- しゃがみジャンプを含む両立可能な同時アクション。
- ジャンプ・しゃがむ・速度変更などのリスク / リターン。
- 成功・失敗・中断・再実行の安定した状態遷移。
- 公式クリアタイムをゲームtickから算出。

### 記録・ランキング

- 各ステージのタイム・文字数・総合ランキング。
- 小さい時間 / 文字数をそれぞれ評価し、スコア表示は高いほど優秀。
- 基準値1000点を超える優秀な解法も許容する。
- 未入力名には一意なゲスト番号。入力名はその文字列を表示。
- 最低限のリクエスト・保存値検証。
- ランキング保存に失敗してもプレイ自体は継続。

### UI・品質

- 自由入力エディタとソフトキーボード。
- 子どもが理解できる文字・ボタン・簡単な説明。
- 複数解法によるレベルデザインと自動実行検証。
- 運営用の端末リセットと体験者の交代導線。
- CI / 回帰テスト。

## 5. 拡張機能（P1 / P2）

| 優先 | 機能 |
| --- | --- |
| P1 | ステージ追加、難易度別コース、ステージ開放 |
| P1 | コイン・スイッチ等のデータ駆動ギミック |
| P1 | キャラクタースプライト、移動 / ジャンプ / しゃがみアニメーション |
| P1 | ステージごとの基準解法集と自動探索の強化 |
| P1 | 文字入力補助（字形・キー配置等。命令選択UIにはしない） |
| P1 | ローカル自己ベスト、プレイ履歴、ランキング再閲覧 |
| P1 | 学園祭運営画面、シーズン切り替え、簡易統計 |
| P2 | 音・背景演出・複数ルート・追加構文（else、変数等） |
| P2 | ステージエディタ、解法の閲覧・共有、実績 |

## 6. 明確に対象外

- QRコード / 復帰コードによる異なる端末間の結果引き継ぎ。
- アカウント、メールアドレス、パスワードによるログイン。
- 文字サイズ変更機能（表示ズレ・調整コストを避ける）。
- Scratch型のブロックパーツや命令ピッカー。
- Tabやインデントの深さによるブロック表現。
- 一般競技サイト級の不正対策、複雑な認証基盤。
- 自動発話や多言語対応など、今年版に必須でない大規模機能。
- プレイヤーがゲーム開始後にキーボード等でキャラクターを直接操作する仕組み。

## 7. 非機能要件

### 安定性・性能

- DOMやCanvasの描画負荷とシミュレーション時間を分離する。
- 正常でないステージJSON、長い文字列、誤った構文で画面が固まらない。
- 低FPSや画面非表示から復帰しても、公式時間が実時間に左右されない。
- ネットワーク不調時はランキングのみ待機・再試行対象とし、ステージ実行は妨げない。

### 保守性・拡張性

- 語彙辞書、文法、AST、Interpreter、物理、描画、ステージ、ランキングを分離。
- 新規ステージは原則としてJSONの追加で作れる。
- 新しいギミックを共通インターフェースで導入できる。
- ソフトキーボードと物理キーボードは同一エディタ状態を共有。
- ゲーム・言語・ステージ・採点のバージョンを保存する。

### プライバシー・最低限の安全

- 実名・メールアドレス等を必須としない。ニックネーム欄には実名を書かない案内を検討。
- 無制限の入力や巨大データ送信は制限する。
- 公開ランキングで表示するのは登録名・順位・記録など最小限。
- 未成年を対象とするため、保存期間・削除手順を明示する（値は運営判断）。
- 共用端末の前利用者の情報は次の開始前に削除する。

## 8. 受け入れの大枠

2026年学園祭向けの最低完成ラインは、既存ステージの安定動作、自由な短縮構文、ソフトキーボード、3種のランキング、スタッフリセット、自動ステージ検証が動作すること。追加ステージとビジュアルの仕上げはこの安定版を確保してから行う。

具体的な受け入れテストは [品質保証](quality-testing.md) を参照。
