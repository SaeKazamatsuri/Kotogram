# P2 攻略の選択肢・限定探索の結果（2026-10-25）

## 実行方法

```powershell
npm run analyze:p2
npm run analyze:competition
npm run validate:stages
npm test
```

`analyze:p2` はステージ21・22・27・28の既知解法と命令の組み合わせだけを対象に、公開の決定論的なGame Coreで固定tickを再実行する。達成率をWorkerの採点と同じ固定小数点で計算し、時間 `ticks/completionBp` と文字数 `characters/completionBp` の二軸で非劣解を抽出する。すべてのプログラムを網羅する最適性証明ではない。

## 今回登録した新しい競技解法

| ステージ | 調整した役割 | 速度と文字数の別解 | 任意目標 |
|---|---|---|---|
| 21 | 最短・総合 | 383tickの高速部分回収、383tickの高速完全回収、670tickの徒歩完全回収、670tickの徒歩部分回収 | 宝箱を開けるかによって100%／65% |
| 22 | 総合 | 570tickの高速、767tickの通常走行、997tickの徒歩 | いずれも100% |
| 27 | 総合 | 624tickの高速、839tickの通常走行、1090tickの徒歩 | いずれも100% |
| 28 | 既存総合を維持 | 665tickの高速、895tickの通常走行、1163tickの徒歩 | いずれも100% |

上記の全解法は登録済みステージ検証で `expectedTicks` を固定し、Workerによる再実行でも検証する。

ステージ21の部分回収では、コインだけ回収すると達成率65%。同じ383tickでも短いソースの部分回収は文字数が21、完全回収は33。完全回収が最速の得点比較で優勢だが、部分回収は総合点で上回りうる。一律に報酬を捨てることが最善というわけではなく、ルートごとに比較する。

## 変更境界

- 公開ステージJSON、Game Coreの速度/衝突判定、Parser、Worker API、スコアの参照値は変更しない。
- 旧記録と現行 `stageVersion` はそのまま維持する。今回は登録済みテスト解法と分析ツールの拡充だけなのでスコープ変更は不要。
- 後続の分岐ゴールと上下移動台は別PRで、エンジン・言語・描画・Worker・ステージ版を一体実装する。
- 小学生の初見クリア率、修正回数、ヒント利用、会場実機と音量は Issue #12 に残す。上位ランキングの均衡と新ギミックは Issue #151 で継続する。
