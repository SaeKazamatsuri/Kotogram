# 2026年 Canvasビジュアル改善 — 実装仕様（#11）

## 結論と実装順序

描画基盤は現行のCanvas 2Dを維持する。p5.js/PixiJSへの移行は行わない。まず「プレイヤー・障害物の状態を見分けられること」と「一貫した画作り」を改善する。Game Coreを変更しないことを必須条件とする。

| 期 | 対象 | 実装境界 | 完了条件 |
| --- | --- | --- | --- |
| V1 | キャラ状態の輪郭 | `app/game/character.ts`, `visuals.ts` | 待機、歩き、走り、跳ぶ、しゃがむ、しゃがみジャンプで異なる輪郭または接地位置。状態間に判別不能な1フレームがない |
| V2 | 障害物の見やすさ | `app/game/obstacles.ts` | 壁・穴・おばけ・閉扉・開扉・未取得コイン・作動前後スイッチが形状と状態で区別できる。絵が危険範囲を誤認させない |
| V3 | 世界観とシーン演出 | `app/game/scenery.ts`, `renderer.ts`, `effects.ts` | day/sunset/twilightの遠景・中景・プレイ面を3層で区別し、障害物/キャラが常に背景より優先して見える |
| V4 | 表現の保守性 | `app/game/renderer.ts`等 | Canvas描画に依存しないGame Core、描画状態から物理への書戻しなし、公式tick・クリア可否不変 |

## V1 キャラクター

- 基準ゲーム領域: `GAME.width=720`, `GAME.height=360`, `GAME.playerWidth=44`, `GAME.playerHeight=56`, `GAME.crouchHeight=36`。これを直接変更せず描画ルートだけで形を整える。
- `resolveCharacterMotion(game, visualTick, idle)` を唯一の視覚派生関数として扱う。入力は読み取りのみ。現在の `walking/running/jumping/crouching/crouch-jumping` と `idle` を描画状態に使う。
- 足接地の見た目は `GAME.groundY` を基準とし、跳躍時の足場影を浮遊高さに応じて変える。しゃがみジャンプは通常ジャンプに色を重ねるだけではなく頭身/脚の姿勢に差をつける。
- キャラクターの振幅・点滅は`visualTick`による視覚演出に限定。タイム計測、衝突判定、発火履歴を絶対に変更しない。
- クリア/失敗/待機の姿勢は `GameCanvas.vue` の状態遷移と整合させ、ブラウザE2Eの起動→失敗→再挑戦・起動→クリアを維持する。

## V2 ギミック

- 壁: 一方向の明暗、上端の接触面と側面の奥行きを統一。物理幅`wallWidth=28`と見た目の主輪郭が対応。
- 穴: 落下範囲（hole.xからhole.x+width）の端を明示。幅可変に追従し、右端/左端が地面の装飾に埋もれない。
- おばけ: 実際の危険範囲を隠さない半透明表現と身体の輪郭を併用。浮遊演出が判定位置を移動したように見せない。
- コイン: 取得前の回転/浮遊は装飾で、`collected`後は描画しない。遊び方の説明文は増やさない。
- スイッチ/扉: `activated`/`open`の状態を形状で表す。色相変化だけに依存しない。
- シルエットの成立が優先。ハイライト/粒子がキャラクターとオブジェクトを隠す場合は演出を抑える。

## V3 背景

- 既存 `resolveScenePalette` のday/sunset/twilightを温存し、世界観の共通トークンを設ける。新たな英語UIラベル、ゲーム画面の説明文、装飾カードは増やさない。
- パララックスは背景（空・山・木）ごとに奥行きを固定し、当たり判定用world座標とは別にする。
- 明滅/パーティクルを減らす場合は既存prefers-reduced-motionを尊重する。低FPS時の落ちこぼれを救うために`elapsedTicks`を操作しない。

## 技術的な不変条件

1. ステージ1〜7の基準解法、失敗解法、公式elapsedTicksと3つのランキング基準は変わらない。
2. 描画関数は`GameState`を変更しない。描画テストは描画前後のStateを比較。
3. 見た目の差分はPlaywrightスクリーンショットで保存し、シーン/走行/ジャンプ/しゃがみジャンプ/扉開閉を目視比較。スクリーンショットの取得は自動化できるが、人間による視認性判定は将来の実機工程。
4. 技術選定は`/experiments/renderer-lab.html` の実測データが揃うまでCanvas 2Dのまま。p5.jsは別ラボでの実験に限定。CDN依存の描画を本番導線に導入しない。

## 着手順とレビュー境界

- PR-1: V1の姿勢/着地と見た目だけ。描画変更以外を含めない。
- PR-2: V2のギミックの輪郭と状態表現。物理パラメータは触らない。
- PR-3: V3の背景統一と視覚負荷抑制。
- 各PRで`npm test`、`npm run validate:stages`、`npm run build`、`npm run generate`、Playwright E2Eを実行する。人が確認する演出画像をPR成果物に含める。

この文書は実装仕様の決定であり、ビジュアル改修本体の実装完了を意味しない。
